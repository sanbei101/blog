## 工具

`AGENT` 通过调用 `python`, `bash`等通用工具已然拥有了大部分能力, 比如要查询天气, 他可能会通过调用 `curl` 查询公开的天气接口
又比如你想让他填一个表格, 他可能会创建一个`csv`文件,或者通过 `python` 调用库生成

但能做不等于做得好,它们可能会浪费大量的上下文,又或者做出的效果不尽人意

本章会介绍一些好用的 `mcp` 或者 `cli` 工具, 如同给骏马装上马鞍,不装也能跑,但是装了能跑的更快更好


## 限制

`AI` 有时候会写出一些质量较低或者不符合我们期望的代码, 最简单的办法当然是写完之后人工 `Review` 一遍,但也有可能我们也疏忽了某个细节 (如某个错误被忽略, 某个地方 `AI` 图省事用了 `any` 等非规范写法)

```go
json.Unmarshal(data, &user) <- 图省事,没有处理错误

const handleDataSubmit = (event: any) => { <- 图省事没有写类型
  const payload = (event.target as any).value;
  updateUser(payload);
};
```

毕竟现在 `AI` 一次生成的代码动辄成百上千行, 长年累月下来, 这些不规范的代码可能就会让我们的项目变成难以维护的屎山,极大的降低项目可读性,提升出现错误时候的排查难度

> 这个时候怎么办呢?

有人会说我引入 `xxx` SKILL,或者我把项目规范写在了 `AGENTS.md` 文件, 这固然是一个办法,但是当 `AI` 生成的代码量很大时,大量的上下文稀释了这些规则,可能还是旧病重发

这个时候就要引入我们古法编程之时常用的`Linter`工具了, 只需要一行规则

> 每次写完代码,确保 `make lint` 通过

就能让 `AI` 自发的认识到自己的错误,并通过工具的提示自我修复,能减少80%的`AI`低级错误
